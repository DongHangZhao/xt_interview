## 第 0 章：你需要准备什么

### 软件清单

| 软件 | 版本要求 | 干什么用的 | 必须吗 |

```
java version "21.0.7" 2025-04-15 LTS

```bash

```bash

## 第 1 章：安装软件

### 1.1 安装 JDK

**下载地址**：https://adoptium.net/temurin/releases/?version=21

**安装步骤**：
1. 下载 `Windows x64 .msi` 文件
2. 双击安装，一路点"下一步"
3. **注意**：安装时可以勾选 "Set JAVA_HOME variable"（设置环境变量）

**验证**：关掉命令行窗口，重新打开，输入 `java -version`

### 1.2 安装 Maven

**下载地址**：https://maven.apache.org/download.cgi （选 `apache-maven-3.9.x-bin.zip`）

**安装步骤**：
1. 解压到任意目录，比如 `D:\maven`
2. 配置环境变量（见下方截图位置）

**配置环境变量（通用方法）**：
```
此电脑 → 右键属性 → 高级系统设置 → 环境变量 → 新建
```

新建一个变量：
- 变量名：`MAVEN_HOME`
- 变量值：`D:\maven\apache-maven-3.9.10`（你的解压路径）

然后找到已有的 `Path` 变量，点"编辑"，新增一行：
```
%MAVEN_HOME%\bin
```

⚠️ **这一步很关键**：一定要先配好环境变量再继续，否则后面会报错。

### 1.3 安装 Node.js

**下载地址**：https://nodejs.org/ （选 LTS 版本）

安装包一路点"下一步"即可，安装程序会自动配好环境变量。

### 1.4 安装 MySQL

推荐用**小皮面板**（phpStudy），图形化操作，对新手友好：

**下载地址**：https://www.xp.cn/

安装后：
1. 打开小皮面板
2. 点「安装」旁边的版本选择，装 MySQL 8.0
3. 点「启动」，等状态变成绿色

## 第 2 章：导入数据库

### 2.1 创建数据库

项目代码启动时会**自动创建表结构**（通过 Flyway），但数据库本身需要你先手动建好。

**方法一：用命令行（推荐）**

打开命令行窗口，依次输入：

```bash
mysql -uroot -p
```

回车后提示 `Enter password:`，输入你的 MySQL 密码（不知道就试 `123456` 或 `root`）。

进入 MySQL 控制台后，执行：

```sql
CREATE DATABASE IF NOT EXISTS `xt_interview` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

看到 `Query OK` 就是成功了。

**方法二：用 Navicat / 小皮面板的 phpMyAdmin**

界面操作建库也是可以的，关键是数据库名叫 `xt_interview`，字符集选 `utf8mb4`。

### 2.2 创建数据库账号（重要！）

**为什么不能直接用 root？**

root 是 MySQL 的超级管理员，什么都能干。如果项目代码有 bug 或者被人注入恶意 SQL，
用 root 连接的话**整个数据库都能被删掉**。用一个权限受限的账号更安全，这叫"最小权限原则"。

在 MySQL 控制台执行：

```sql
CREATE USER IF NOT EXISTS 'admin'@'localhost' IDENTIFIED BY '123456';
GRANT ALL PRIVILEGES ON `xt_interview`.* TO 'admin'@'localhost';
FLUSH PRIVILEGES;
```

**这几行 SQL 是什么意思**：

| 这行 | 作用 |
|------|------|
| `CREATE USER ... IDENTIFIED BY '123456'` | 创建一个叫 admin 的用户，密码 123456 |
| `ON \`xt_interview\`.*` | 只授权操作 xt_interview 这个库，其他库碰不到 |
| `FLUSH PRIVILEGES` | 让权限立刻生效 |

> 如果提示账号已存在，换成 `ALTER USER` 开头：
> ```sql
> ALTER USER 'admin'@'localhost' IDENTIFIED BY '123456';
> ```

### 2.3 修改项目的数据库配置

打开项目文件夹，用记事本或 VSCode 打开这两个文件：

**文件 1**：`src/main/resources/application.properties`

找到这几行，改成：
```properties
spring.datasource.url=jdbc:mysql://localhost:3306/xt_interview?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
spring.datasource.username=admin
spring.datasource.password=123456
```

**文件 2**：`src/main/resources/application-dev.properties`

改成：
```properties
spring.datasource.url=jdbc:mysql://localhost:3306/xt_interview?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
spring.datasource.username=admin
spring.datasource.password=123456
```

> 💡 **小技巧**：配置里写的是 `${DB_USERNAME:admin}` 这种格式，
> 意思是"优先读环境变量 `DB_USERNAME`，没有的话就用冒号后面的默认值 admin"。
> 这样你本地直接跑能通，将来部署到服务器时也不用改代码。

## 第 3 章：启动后端

### 3.1 打开项目文件夹

命令行窗口 `cd` 到项目根目录（就是有 `pom.xml` 那个文件夹）：

```bash
cd F:\XM\ai\xt_interview\xt_interview-master
```

> 提示：路径里如果有空格，用引号包起来，例如 `cd "D:\my project"`

### 3.2 执行启动命令

```bash
mvn spring-boot:run
```

### 3.3 怎么知道启动成功了？

屏幕上会出现这样的日志：

```
Tomcat started on port 8080 (http) with context path '/'
Started XtInterviewApplication in 6.2 seconds
```

看到这两行就成功了。

> **看到这一行也正常**：
> ```
> Migrating schema `xt_interview` to version "1 - sys account"
> Successfully applied 1 migration
> ```
> 这是在建表，第一次启动会看到，第二次就不会了。

### 3.4 验证后端活着

浏览器打开：
```
http://localhost:8080/api/auth/validate
```

看到 `{"valid":false,"message":"未提供token"}` 就说明**后端跑起来了**。
（这个接口需要登录才能用，所以这里报错是正常的）

⚠️ **这个窗口不要关**，关了后端就停了。

## 第 5 章：登录并体验所有功能

### 5.1 三个账号分别是什么

| 身份 | 用户名 | 密码 | 能看到什么 |
|------|--------|------|-----------|
| 🔴 超级管理员 | `emp_admin` | `123456` | 全部功能，能管所有账号和部门 |
| 🟡 部门管理员 | `emp_dev_mgr` | `123456` | 能管用户和部门，但管不了同级 |
| 🟢 普通员工 | `emp_dev01` | `123456` | **只能看到自己的信息** |
| ⚫ 禁用账号 | `emp_leave01` | `123456` | 登录会被拒绝（演示账号禁用效果） |

> 另外还有一个初始账号 `admin` / `123456`，密码同样是 `123456`。

### 5.2 用不同账号登录，感受权限差别

**这是本项目最重要的体验点**，一定要三个账号都试一遍：

#### 用普通员工 `emp_dev01` 登录

你会看到：
- 左侧菜单**只有「个人中心」**一项
- 看不到「用户管理」和「部门管理」
- 就算在地址栏手动输入 `http://localhost:5173/users`，也会自动跳回个人中心

在个人中心可以改自己的姓名、手机号、用户名、密码。

> ⚠️ 注意：个人中心里**没有**权限级别、所属部门、账号状态这三个字段。
> 这是故意的 —— 这些属于管理字段，只能由管理员分配，用户不能自己改。

#### 用部门管理员 `emp_dev_mgr` 登录

你会看到：
- 左侧菜单有「用户管理」和「部门管理」
- 可以添加/编辑/删除用户和部门
- 但用户列表里，超管和其他管理员的行会显示"**无权限**"（按钮变灰不可点）

试试这些操作，感受被拦截的感觉：
1. 在用户列表点超管的「编辑」→ 看不到按钮
2. 新增用户时，"权限级别"下拉框里**只有「用户权限」**一个选项
3. 创建一个部门，往里面放 2 个用户，然后尝试删这个部门 → 提示"该部门下还有 2 个用户，无法删除"

#### 用超管 `emp_admin` 登录

你能看到全部 50 个账号、21 个部门，所有操作都能做。
新增用户时，权限下拉框里三个选项全都有。

### 5.3 试试"越权被拦截"的效果

这是最能体现项目安全性的地方，面试时可以直接演示：

**用普通员工账号登录，然后在浏览器按 F12 打开开发者工具**，在 Console 里执行：

```javascript
// 尝试用普通用户的身份创建管理员
await axios.post('/api/accounts', {
  username: 'hacker', name: '黑客', roleLevel: 2, status: 1
}, { headers: { Authorization: 'Bearer ' + localStorage.getItem('token') } })
```

回车后会看到返回：
```json
{"success":false,"message":"权限不足，仅管理员及以上可创建账号"}
```

**同样的请求如果用普通账号在页面上操作，是点不出这个错误的**，因为前端菜单已经藏起来了。
后端这道防线才是真正的安全边界。

## 第 6 章：常见操作速查

### 6.1 怎么停止服务

在跑着服务的那个命令行窗口里，按 `Ctrl + C`。

### 6.2 怎么重新启动

```bash
# 后端
cd F:\XM\ai\xt_interview\xt_interview-master
mvn spring-boot:run

# 前端
cd F:\XM\ai\xt_interview\xt_interview-master\frontend\web
npm run dev
```

### 6.3 数据库里有多少数据

命令行方式：

```bash
mysql -uadmin -p xt_interview
```

进去后：
```sql
-- 看有多少部门
SELECT * FROM sys_department;

-- 看所有用户
SELECT id, username, name, department_id, status, role_level FROM sys_account;

-- 看用户属于哪个部门（联表查询）
SELECT a.username, d.name AS 部门
FROM sys_account a
LEFT JOIN sys_department d ON a.department_id = d.id
WHERE a.deleted = 0;
```

### 6.4 想重置数据库（回到刚装好的样子）

⚠️ **警告：下面这条命令会删掉所有数据，不可恢复！**

```sql
-- 先删 Flyway 记录
DELETE FROM flyway_schema_history;
-- 再删所有表
DROP TABLE IF EXISTS sys_account;
DROP TABLE IF EXISTS sys_department;
```

然后重启后端，Flyway 会自动把所有表和测试数据重新建好。

### 6.5 怎么改自己的密码

有两种方式：
1. 登录后进「个人中心」，改「新密码」
2. 直接在数据库里改：
```sql
-- 123456 的 MD5 值
UPDATE sys_account SET password = 'e10adc3949ba59abbe56e057f20f883e' WHERE username = '你的用户名';
```

## 第 7 章：出问题了怎么办

### 问题 1：提示 `Port 8080 was already in use`

**意思**：8080 端口被别的程序占了。

**解决**：
1. 找到占用的程序并关掉：
   ```bash
   netstat -ano | findstr :8080
   ```
   记下最后一列的 PID 号，然后：
   ```bash
   taskkill /PID 这里填PID号 /F
   ```
2. 或者换个端口启动：
   ```bash
   mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8081"
   ```
   （改了端口记得同步改前端 `vite.config.ts` 里的代理配置）

### 问题 2：提示 `Access denied for user 'admin'@'localhost'`

**意思**：数据库密码不对，或者账号没建。

**解决**：
1. 用 root 登录：
   ```bash
   mysql -uroot -p
   ```
2. 重置 admin 的密码：
   ```sql
   ALTER USER 'admin'@'localhost' IDENTIFIED BY '123456';
   GRANT ALL PRIVILEGES ON `xt_interview`.* TO 'admin'@'localhost';
   FLUSH PRIVILEGES;
   ```

### 问题 3：提示 `Unknown database 'xt_interview'`

**意思**：数据库没建。

**解决**：
```sql
CREATE DATABASE `xt_interview` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 问题 4：提示 `Unsupported class file major version`

**意思**：JDK 版本不对。

**解决**：确认 `java -version` 显示的是 21 或更高。
如果是低版本，去 [1.1 安装 JDK](#11-安装-jdk) 重装。

### 问题 5：前端页面打开是空白

**原因**：一般是后端没启动，或者前端代理没配好。

**排查步骤**：
1. 先确认后端活着：浏览器访问 `http://localhost:8080/api/auth/validate`
2. 如果后端正常，看命令行窗口里前端有没有报红字
3. 尝试重启前端：`Ctrl+C` 停掉，再 `npm run dev`

### 问题 6：登录时提示"用户名或密码错误"

**原因**：数据库里没有这个账号。

**解决**：检查数据库里有哪些账号：
```sql
SELECT username, status FROM sys_account WHERE deleted = 0;
```

如果表是空的，说明 Flyway 没跑成功，删掉数据库重建：
```sql
DROP DATABASE xt_interview;
CREATE DATABASE xt_interview DEFAULT CHARACTER SET utf8mb4;
```
然后重启后端。

### 问题 7：改了 Flyway 脚本后启动报 `failed migration`

**意思**：Flyway 记录了迁移失败状态，之后每次启动都会报错。

**解决**：
```sql
DELETE FROM flyway_schema_history WHERE success = 0;
```
然后重启后端。

> 根本原因：Flyway 的迁移脚本一旦执行成功就**不允许再修改**。
> 要改已执行过的脚本，必须新建一个编号更大的脚本（比如 V6）。

### 问题 8：Vite 端口自动变成 5174

**原因**：5173 已经被占用了（可能之前启动的前端没关）。

**解决**：
```bash
netstat -ano | findstr :5173
taskkill /PID 这里填PID号 /F
```
然后重新 `npm run dev`。

│   │   ├── XtInterviewApplication.java   ← 程序入口（不用改）

│   │   │   ├── SecurityConfig.java       ← 权限配置
│   │   │   └── WebMvcConfig.java         ← 跨域配置

    ├── vite.config.ts                    ← 前端配置（含代理）
    └── src/
        ├── api/index.ts                  ← 所有接口请求封装在这
        ├── router/index.ts               ← 页面路由 + 权限守卫
        ├── stores/user.ts                ← 登录状态存这
        ├── utils/request.ts              ← 请求拦截器（带 token）
        ├── layouts/MainLayout.vue        ← 左侧菜单框架
        └── views/
            ├── Login.vue                 ← 登录页
            ├── UserManagement.vue        ← 用户管理页
            ├── DepartmentManagement.vue  ← 部门管理页
            └── Profile.vue               ← 个人中心
